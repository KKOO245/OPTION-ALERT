# OPTION-ALERT P0.1 事件引擎使用说明

## 是什么

P0.1 实现的是企划书"数据主链"的地基：

```
快照 → 机械 Setup 检测 → 事件（不可变 JSONL + 哈希链）→ Outcome 回填
     → Episode 聚类 → 验证摘要（Base Rate / Lift / CI）→ 报告渲染
```

这一阶段**不做**漂亮报告、不做方向判断（Decision 恒为 WATCH 占位）、不引入新指标。
核心目标是从第一天起积累干净、不可篡改、可回溯的 Thesis Event 数据。

## 运行要求

- Python 3.10+，**零第三方依赖**（本阶段刻意不用 pandas/pyyaml）。
- 配置文件使用受控 YAML 子集（`engine/yaml_mini.py`），遇到不支持的语法会直接报错，不会静默误解析。
- 测试无需 pytest：`python tests/run_all.py`；装了 pytest 也可以用 `pytest tests/`。

## 常用命令

```bash
python main.py store-snapshot snapshot.json          # 校验并存储快照
python main.py build-snapshot --ticker SOXX --session morning   # 用旧 analytics 历史回溯生成快照
python main.py detect                                 # 处理最近一次快照
python main.py detect --date 2026-08-21 --all         # 处理某天全部标的
python main.py evaluate --ticker SOXX                 # 自动用 analytics 生成价格序列回填结果
python main.py evaluate --prices p.csv --rv r.csv --calendar cal.txt --as-of 2026-08-28
python main.py invalidate SOXX_20260821_A_001 --reason "规则Bug，作废"
python main.py episodes --calendar cal.txt
python main.py validate --prices p.csv --calendar cal.txt
python main.py report --session morning
python main.py audit
```

**P0.2 第一步已落地——真实数据 → snapshot_v1 适配层**：

- 实时模式（你本机，需要现有 requirements）：`python src/pipeline_snapshot.py --ticker SOXX --session morning`
  CBOE 期权链 → `compute_metrics()` → snapshot_v1 → 入库。不修改现有 `options_report.py`。
- 方案 A 落地后（GitHub 运行）：`src/options_report.py` 已内置快照入库钩子，
  workflow 在报告后自动跑 `detect / episodes / evaluate` 并提交数据，无需本地执行。
- 回溯模式（纯标准库，本仓库直接可跑）：`python main.py build-snapshot --ticker SOXX --session morning`
  用旧 `data/analytics/{ticker}.csv` 的历史行生成快照；结构类字段（Walls/GEX/Flip）当年没持久化，
  一律诚实标 `INSUFFICIENT_DATA`，不会补数。
- 适配层纪律：`iv_momentum` = 相对历史 20 期 IV 分布的 z-score（不足 20 期 → N/A）；
  `iv_momentum_1d` 才是当日环比（百分点，供确认层）；`put_buy_flow`/`volume_surge`
  在聚合数据下不可判定 → 一律 INSUFFICIENT。

生产环境把数据目录指向本地固定路径：

```bash
set OPTION_ALERT_DATA_ROOT=D:\option-alert\data
python main.py --data-root %OPTION_ALERT_DATA_ROOT% detect
```

## 数据流与文件

| 阶段 | 输出 | 说明 |
|---|---|---|
| 快照 | `analytics/daily/YYYY-MM-DD/TICKER_{session}.json` | 校验 + 自动标注缺失字段 + snapshot_hash |
| 检测 | `thesis/events.jsonl` + `thesis/audit.jsonl` | append-only；审计记录每个 Setup 是否被机械检查 |
| Outcome | `thesis/outcome_revisions.jsonl` | 追加 revision，幂等，不修改原始事件 |
| 聚类 | `episodes/episodes.jsonl` | 派生视图，确定性重算 |
| 验证 | stdout | 条件率 / Base Rate / Lift / CI / 数据充分性标签 |

## 纪律要点（代码里已强制）

1. 事件写入前先校验哈希链，发现篡改/断裂拒绝继续写入。
2. Outcome 只能以 revision 追加；`CONFIRMED/REJECTED/EXPIRED/INVALIDATED` 语义写死。
3. 锚点/终点收盘只取精确匹配——缺数据判 `INSUFFICIENT_DATA`，不用"下一个收盘"悄悄后移起点。
4. `detect` 幂等：同一 (snapshot_hash, setup_id) 不会重复建事件。
5. 所有测试 fixture 均为合成数据，`source=SYNTHETIC_TEST_FIXTURE`，绝不冒充真实行情。

## P0.1 已知边界（诚实清单）

- Decision 恒为 WATCH：Edge/Gate 计算层属于 P0.2，本阶段不产生方向判断。
- Base Rate 用重叠窗口，仅初步参考；正式版按窗口结束日打分/起始日聚类。
- 工作日历缺省按 Mon-Fri 近似；生产环境应传入完整交易日历。
- 单标的统计力不足问题依旧存在，需按企划书跨标的积累独立 Episode。

更多运维说明见 `docs/方案A-GitHub运行与本地镜像.md`。
