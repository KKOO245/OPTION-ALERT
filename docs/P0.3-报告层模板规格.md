# P0.3 报告层模板规格（v1）

> 版本：v1（2026-08-23 冻结草案）｜ 范围：晨报 / 晚报 / 多标的压缩 / 展示规则
> 上位原则：企划书报告纪律第一条——**所有分析基于真实数据；不假设、不编造；拿不到就标 Unknown / INSUFFICIENT_DATA**。

## 0. 设计定位

- **Data → Information → Decision**：Discord 只展示机械规则生成的内容；原始数据全部留存在 `thesis/`、`analytics/daily/`、`state/`。
- **展示层与数据层分离**：所有数字可溯源到快照；报告只负责压缩与标注，不新增任何未计算的数字。
- **Gate 未上线前不渲染 Decision**：方向结论由 P0.2 Decision Gate 产生；上线前报告只给"事实 + 状态"。
- **模型层输入只进 Setup 触发，不进方向决策**：GEX/Wall/Flip 可用于触发判定，但不得作为方向结论的依据。
- **Decision Relevant，不是 Data Rich**：系统先判断哪些数据对当前 Thesis 有用，再只展示有用数据；原始数据全部进后台。

## 1. 通用展示规则

### 1.1 数据来源与溯源
- 每个数字必须来自快照（`analytics/daily/YYYY-MM-DD/TICKER_{session}.json`）或 thesis 事件。
- 报告尾部固定一行"数据溯源"：指向附录 / thesis / 对应快照路径。
- 对比区优先使用 thesis 事件（若昨日有 Setup 事件）；无事件时用昨日快照字段；昨日快照缺失 → 显示"昨日快照缺失"，不补数。

### 1.2 单位规范（写死，所有数字必须带单位或固定口径）

| 字段 | 单位/口径 |
|---|---|
| GEX / Vanna / Charm | 美元（$，按 OI×100×spot 口径） |
| 净Δ / 今日Δ | 股 |
| ATM IV | % |
| IV Rank | 百分位 % |
| 25Δ Skew | pp |
| 预期波动 ExpMove | ±% |
| 距关键位距离 | %（相对该行权价） |
| P/C 量比 / OI 比 | 无量纲倍数 |
| ΔOI/Volume | %（= \|ΔOI\| ÷ 当日成交量） |

### 1.3 注解规则
- **所有展示行/事件卡一律附注解**（用户自行判断可信度，系统只给事实和规则推断）。
- 注解长度上限：**2 行，单行 ≤ 30 字**（Options 行等需要完整解释的可用 2 行）。
- 注解由机械规则生成（见 1.6），禁止手写、禁止方向词。
- **禁用词**：买/卖（作为方向断言）、开仓/平仓（作为确认流）、看多/看空、转弱/走强、避险买盘、偏空/偏多（作为注解标签）。
- **允许词**：净增/净减、换手、分歧、放量（仅完整度=高时）、疑似（仅用于"规则推断"，且必须附"方向未知"）。
- **Options 注解固定三段式**（纯事实，方向 Unknown）：

```
Put/Call Volume: 3.10×（Put 成交显著高于 Call）→ 方向 Unknown
Put/Call OI: 0.70×（Put OI 低于 Call OI）→ 存量 Call-dominant
两者结构不一致
```

### 1.4 未验证研究层标注
- GEX / Call-Put Wall / Gamma Flip / 做市商对冲行，统一前缀"模型层"或整块标注：

```
未验证研究层：Mechanism Scenario——
Scenario A：若 OI 主要对应客户买入、做市商卖出，则（结论 A）；
Scenario B：若为客户卖出、做市商买入，则方向可能相反。
OI 开仓方向不可观测。
```

- 做市商相关结论格式：**结论在前 + ⚠️ 假设警告在后**（见 1.5）。
- **Flip 展示纪律**：报告写 `模型隐含 GEX 过零点 ≈ 523.5（Scenario 依赖）`，禁止写成精确市场结构；全链重定价上线前仍标"Top-3 近似，需重定价验证"。

### 1.5 做市商对冲行（固定格式）

```
条件机制：若 Scenario A（客户买开/做市商卖开）+ 负 Gamma 成立，跌破 500 下方可能对应顺周期卖出压力增加；
实际做市商对冲流量不可观测。
⚠️ Scenario B（客户卖开/做市商买开）→ 方向相反。不进入方向决策。
```

### 1.6 变动等级 / 完整度 / 注解规则（预提交）

**变动等级（复合规则，v1）**：

| 分量 | 公式 | 计分 |
|---|---|---|
| r1 | \|ΔOI\| ÷ 当日成交量（展示名：ΔOI/Volume） | ≥5%→1分；≥20%→2分 |
| r2 | \|ΔOI\| ÷ 前日 OI | ≥5%→1分；≥20%→2分 |
| r3 | \|ΔOI\|（张） | ≥50→1分；≥500→2分 |

| 等级 | 总分 |
|---|---|
| 低 | 0-1 分 |
| 中 | 2-3 分 |
| 高 | 4-6 分 |

**展示要求**：事件卡必须显示判定依据的原始值——**ΔOI/Volume（%）与 \|ΔOI\|（张）**——等级标注紧随其后。等级字段名 = **Activity Magnitude（结构变化幅度：LOW/MEDIUM/HIGH）**，测量的是 OI 结构变化幅度，不是"重要性"，也不是流向置信度；禁止把幅度解释成"确定是重要资金"。历史分位分量待 ≥20 期数据后加入（v2）；v1 阈值跨标的统一，为经验默认，开 v2 时需校准。

**事件卡字段冻结**：仅 Vol / OI 前→现 / ΔOI / ΔOI/Volume / Magnitude / 完整度 + 注解；在获得可靠 trade-level 数据前，不再增加 premium flow / aggressor / 买卖方向等字段。

**数据完整度**：今量+昨量+昨OI+今OI 全有 → 高；缺昨量或昨OI → 低；其余 → 中。

**注解模板**（机械生成）：

| 事件类型 | 注解模板 |
|---|---|
| 低等级 | 净增仓仅占量X%，以日内换手为主 / 净减仓仅占量X%，以日内换手为主 |
| 中等级 | 放量且净增X张（+Y%），值得跟踪（方向未知） |
| 高等级 | 大额净增X张（+Y%），连续性待观察（方向未知） |

说明：注解中的"放量"字样只在完整度=高时出现（有昨量基准）；否则只报净变动数字。

### 1.7 缺失与降级处理
- 历史不足 → `Rank — (历史不足)`；不可判定 → `?`（附缺失字段名，如"趋势 ?(prev_close缺失)"）。
- 当日晨报缺失时，晚报 Scorecard 显示"晨报缺失（原因）"，只报收盘事实，不编造条件。
- Gate 未上线或 Setup 未达资格 → `decision = NOT_RENDERED`（WATCH 也是一种决策，未达资格不产生任何结论）。

## 2. 晨报模板（含昨日晚报 → 今日晨报对比区）

### 2.1 结构

```
# 期权晨报 YYYY-MM-DD

## 对比区：昨日晚报 → 今日晨报（只列关键项）
<ticker> 昨收 X → 今晨 Y（±%）| 较昨收变动 ±Z%（含盘初走势）| 距 Put Wall: ±%
Setup 状态: 昨日(状态) → 今晨(状态)
IV / P/C量 / GEX: 昨日值 → 今晨值（±变化）
OI净变动: 昨日(等级) → 今晨(等级)

## 每标的（有 Setup 或中高变动 → 展开；否则一行）
```

跨时段对比口径：对比区所有变化标注基准（vs 昨日晚报）；IV 类字段跨早/晚时段对比时加注"盘中/收盘口径"。
较昨收变动 = 今晨价 ÷ 昨收 − 1（10:15 快照含盘初走势，不叫"隔夜跳空"；如需纯跳空，快照需增加 open 字段）。

**变化显示阈值**（低于阈值不单列，合并为"无显著变化"）：

| 字段 | 阈值 |
|---|---|
| 价格 | ±0.5% |
| IV | ±0.5pp |
| P/C量 | ±0.2 |
| GEX（存量） | ±20% 或 ±1M |
| Setup 状态 | 任何变化都显示 |

对比区只列变化，不重复正文的今日值。

### 2.3 多标的压缩（两级）

- **展开**：有 Setup 触发，或 Activity 变动等级 ≥ 中。**不设硬上限**——波动大、多标的满足条件时全部展开属正常。
- **一行带过**：无 Setup 且无中高变动：
  `SOXX $515.80 | 无Setup | 结构参考: 500(下) / 670(上)`
- 对比区同样两级压缩：有变化的标的展开一行，无变化的不出现或合并。

## 4. 与 P0.2 的边界

- P0.2（Edge/Gate 计算层）未上线前，报告不渲染 Decision，不显示"短线倾向/综合分"等未校准启发式。
- Setup 触发允许使用模型层输入（如 gamma regime），事件记录时标注"输入来自模型层"；但模型层输入不进入 Direction Edge。
- 全链重定价（Regime Map）为 P0.2/P1 计算项；上线前 Flip 结论一律标注"Top-3 近似，需重定价验证"。
- Gate 原则：**Gate 不创造 Alpha，只过滤已验证的 Setup**。Core 资格用精确条件：**OOS Lift ≥ +5pp 且 95% CI 下界 > 0**（不使用"不明显跨无效区"这类模糊措辞）。
- Confirmation 只做三态计数（✓/✗/?，如 2/4），不计算"命中率"，不进入任何 Edge 合成。
- Target 显示纪律：评价窗口未结束前，只显示 `Target: … — PENDING（evaluation date …）`；到窗口结束时才允许 CONFIRMED / REJECTED。

## 5. 版本管理

- 本规格为 v1；任何展示字段、规则阈值、注解模板的修改 = 新版本（v2…），旧报告不回溯修改。
- 阈值（变动等级、完整度、注解触发）跨标的全局统一，不按 ticker 调参。

## 7. v1.1 更新（2026-08-26）

### 7.1 重点速览（highlight_v1）
- 每标的报告开头固定渲染 `🔍 重点速览`，规则见 `config/thresholds.yaml → highlight`。
- 级别：🔴 关键（事件差分 ≥15pp / Gamma Regime 切换 / Vol Regime 升档）/ 🟡 关注（近现价集中开仓 ≤±5%、单日价格波动 ≥2%、事件差分 10–15pp）/ 🔵 信息（期限 OI 集中 ≥10%、Flip CONDITIONAL）。
- 上限 3 条/标的；无满足项显示"今日无重点项"；highlight 是提醒注意，不是方向信号。
- Discord 推送附加单张 Embed 彩色侧条（红/黄/蓝，≤1500 字符）；Embed 发送失败自动降级为纯文本，保证正文一定送达。

### 7.2 事件差分（event_diff_v1）
- 覆盖判定：事件日期 > 上一期限到期日 且 ≤ 本期限到期日；对照组 = 相邻下一期限。
- 输出：`覆盖期限 ATM IV vs 对照期限 ATM IV（差 +X.Xpp）`，标注"观察，非因果"与美联储 IFDP 1376 实证来源；单日截面需连续多日确认。
- 阈值与规则见 `config/thresholds.yaml → event_differential`。

### 7.3 ExpMove 期限化（expmove_v1）
- Options 行保留近端单值（标注"近端"），下方新增逐期限行：`08-28（2D）±5.8% ｜ …`。
- 公式：`(ATM Call + ATM Put) ÷ spot × 100`，逐结算日独立计算；旧快照缺字段时渲染层用同公式兜底。

### 7.4 Flip 状态机（flip_status_v1）
- 快照 `location` 新增 `flip_candidates` / `flip_primary` / `flip_reason`。
- 状态：PRIMARY（全链重定价+覆盖达标，quality gate 冻结前不输出）/ CONDITIONAL（当前默认，Top-3 近似）/ NO_CROSS（带内无穿越）/ INSUFFICIENT_DATA。
- 报告显示：`Flip: Candidates … ｜ Primary: N/A（CONDITIONAL）`；不再并列显示多个"≈"。

### 7.5 测量完整性行
- 结构块新增一行：GEX 符号契约（gex_sign_v1，Model A）+ Gamma 口径（Top-3）+ Effective GEX 覆盖/IV 有效性（待盘点/待审计）。
- 数据质量（行情/期权结构/流向/做市商机制 A/B/C）每标的末尾显示。

### 7.6 Possible Roll 候选（后台字段，不进报告/评分）
- `forward.expirations[].roll_candidates`：同期限同类型一正一负大额 ΔOI（≥ roll_candidate_min_abs）配对，confidence = MEDIUM（行权价差 ≤10%）/ LOW；仅存 analytics JSON。

### 7.7 最近结构参考
- 结构块新增一行：距现价最近的结构位（Put Wall / Call Wall / Flip 候选）及其距离。
